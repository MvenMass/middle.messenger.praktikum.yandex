# Messenger

Учебный проект для курса Яндекс Практикума. Делаю свой мессенджер, похожий по идее на телеграм.

Проект закончен: приложение работает с API Практикума, сообщения приходят в реальном времени через WebSocket, основные модули покрыты тестами.

## Как запустить

Нужен Node.js 22 или новее.

```bash
npm ci
```

- `npm run dev`: режим разработки на http://localhost:3000
- `npm run build`: проверка типов и сборка в папку dist
- `npm run start`: собрать и запустить готовую версию на порту 3000
- `npm run lint`: проверка типов (tsc), ESLint и Stylelint

## Тесты

- `npm test`: один раз запустить все тесты
- `npm run test:watch`: запускать тесты заново при каждом изменении файлов

Тесты написаны на Jest с окружением jsdom и лежат рядом с модулями, которые проверяют: `block.test.ts` рядом с `block.ts` и так далее. Покрыты `Block`, роутер, `HTTPTransport`, `WebSocketTransport`, компоненты формы и утилиты.

Шаблоны Handlebars подключаются через Vite-импорт `?raw`, Jest такой синтаксис не понимает. Поэтому в папке `jest` лежат два маленьких помощника: один убирает `?raw` из пути, второй превращает файлы `.hbs` и `.scss` в строки.

Перед каждым коммитом Husky запускает lint-staged (ESLint и Stylelint проверяют только изменённые файлы), проверку типов TypeScript и все тесты. Если что-то не прошло, коммит не создаётся.

## Страницы

| Адрес | Страница | Кому доступна |
|---|---|---|
| `/` | вход | только гостям |
| `/sign-up` | регистрация | только гостям |
| `/messenger` | чаты и переписка | только после входа |
| `/settings` | настройки профиля | только после входа |
| `/404` | страница не найдена | всем |
| `/500` | ошибка сервера | всем |

Любой неизвестный адрес показывает страницу 404. Гостя со страниц для авторизованных перекидывает на вход, а вошедшего пользователя со входа и регистрации перекидывает в чаты.

## Что умеет приложение

- Регистрация, вход и выход.
- Профиль: изменение данных, пароля и аватара.
- Чаты: список, поиск по названию прямо во время ввода, создание и удаление чата, смена аватара чата.
- Участники: добавление по логину, удаление из списка участников чата.
- Сообщения в реальном времени: отправка и получение через WebSocket. При открытии чата загружаются последние 20 сообщений, кнопка «Показать ранние сообщения» подгружает следующие 20. После перезагрузки страницы и при переключении между чатами история подгружается заново.
- При обрыве соединения с чатом появляется надпись «Нет соединения, переподключаемся…», приложение переподключается само. Если отправить сообщение без соединения, под полем появится «Нет соединения с чатом, сообщение не отправлено», а текст останется в поле.
- Все формы проверяются при потере фокуса и при отправке, ошибки сервера показываются понятным текстом.
- На узком экране список чатов и переписка открываются по очереди, из чата можно вернуться кнопкой «Назад».

## Как устроено

- `Block`: базовый класс компонентов с жизненным циклом (`componentDidMount`, `componentDidUpdate`, `componentWillUnmount`).
- Роутер на History API с проверкой авторизации через middleware. На экране всегда одна страница, старая удаляется из DOM.
- `HTTPTransport` на XMLHttpRequest и Promise: GET, POST, PUT, DELETE, query string для GET, JSON или FormData в теле запроса.
- `WebSocketTransport`: подключение к чату, ping каждые 15 секунд, разбор входящих сообщений.
- Ошибки разделены на классы: `HttpError`, `UnauthorizedError`, `ServerError`, `NetworkError`, `TimeoutError`, `SocketConnectionError`, `SocketClosedError`.
- `Store` и функция `connect`: компонент подписывается на нужную ему часть данных и перерисовывается только при их изменении.

## Безопасность

- Весь текст от пользователей и сервера выводится через экранирование Handlebars (`{{ }}`). Тройные скобки используются только для вставки компонентов.
- В `index.html` задан Content-Security-Policy: скрипты загружаются только с самого сайта, запросы уходят только к API Практикума. Чужие скрипты и обработчики вроде `onerror` в разметке не выполнятся.
- Cookie авторизации ставит сервер с флагом HttpOnly, из JavaScript они недоступны.
- Зависимости обновлены, `npm audit` не находит уязвимостей, версии зафиксированы точно. Уязвимые версии `glob` и `minimatch`, которые приходят вместе с Jest, подняты до исправленных через `overrides` в `package.json`.

## Архитектура

Проект разделён по MVC:

- **View**: компоненты и страницы, наследники `Block`, разметка в Handlebars-шаблонах.
- **Model**: API-классы для запросов, `Store` с состоянием приложения, сервисы с валидацией и подготовкой данных для шаблонов.
- **Controller**: контроллеры получают данные из форм, вызывают API, кладут ответ в `Store` и делают переходы между страницами.

```
src/
  api/          - запросы к API, по классу на сущность
  core/         - Block, EventBus, Router, HTTPTransport, WebSocketTransport, классы ошибок
  components/   - переиспользуемые компоненты, у каждого своя папка с index.ts
  pages/        - страницы, в pages/messenger/blocks блоки, нужные только чату
  controllers/  - контроллеры авторизации, пользователя, чатов и сообщений
  store/        - Store и connect
  services/     - валидация, сбор данных форм, тексты ошибок, подготовка данных
  models/       - типы данных
  utils/        - queryStringify и isEqual
  routes.ts     - адреса страниц и экземпляр роутера
  main.ts       - точка входа: маршруты, проверка доступа, запуск
ui/             - картинки с макетами
```

Иконки, аватар и сообщение подключены как Handlebars-партиалы. Имя иконки берётся из файла: `icon-send.hbs` в шаблоне вызывается как `{{> IconSend}}`.

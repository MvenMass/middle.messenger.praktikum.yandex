# Messenger

Учебный проект для курса Яндекс Практикума. Делаю свой мессенджер, похожий по идее на телеграм.

Сейчас закончен третий спринт: приложение работает с API Практикума. Можно зарегистрироваться, войти, поменять данные профиля, аватар и пароль, создавать чаты и добавлять в них людей. Переписка в реальном времени появится в следующем спринте.

## Как запустить

Нужен Node.js 22 или новее.

```bash
npm install
```

- `npm run dev`: режим разработки на http://localhost:3000
- `npm run build`: проверка типов и сборка в папку dist
- `npm run start`: собрать и запустить готовую версию на порту 3000
- `npm run lint`: проверка типов (tsc), ESLint и Stylelint

## Страницы

| Адрес | Страница | Кому доступна |
|---|---|---|
| `/` | вход | только гостям |
| `/sign-up` | регистрация | только гостям |
| `/messenger` | чаты | только после входа |
| `/settings` | настройки профиля | только после входа |
| `/404` | страница не найдена | всем |
| `/500` | ошибка сервера | всем |

Любой неизвестный адрес показывает страницу 404. Гостя со страниц для авторизованных перекидывает на вход, а вошедшего пользователя со входа и регистрации перекидывает в чаты.

## Что сделано

- Роутер на History API: переходы без перезагрузки, работают кнопки «Назад» и «Вперёд», после F5 открывается та же страница. На экране всегда одна страница, старая удаляется из DOM.
- Проверка авторизации в роутере через middleware.
- Класс `HTTPTransport` на XMLHttpRequest и Promise: методы GET, POST, PUT, DELETE, query string для GET, JSON или FormData в теле запроса, отправка cookie.
- Ошибки запросов разделены на классы: `HttpError`, `UnauthorizedError`, `ServerError`, `NetworkError`, `TimeoutError`. Пользователь видит понятный текст ошибки под формой.
- Регистрация, вход и выход. После входа или регистрации открываются чаты.
- Настройки: изменение данных профиля, пароля и аватара.
- Чаты: загрузка списка, создание чата, добавление и удаление пользователя по логину.
- Глобальное хранилище `Store` и функция `connect`, которая подписывает страницу на нужную ей часть данных и перерисовывает её только при изменении этих данных.
- Свои утилиты `queryStringify` и `isEqual`.

## Архитектура

Проект разделён по MVC:

- **View**: компоненты и страницы, наследники `Block`, разметка в Handlebars-шаблонах.
- **Model**: API-классы для запросов, `Store` с состоянием приложения, сервисы с валидацией и подготовкой данных для шаблонов.
- **Controller**: контроллеры получают данные из форм, вызывают API, кладут ответ в `Store` и делают переходы между страницами.

```
src/
  api/          - запросы к API, по классу на сущность
  core/         - Block, EventBus, Router, Route, HTTPTransport, ошибки запросов
  components/   - переиспользуемые компоненты, у каждого своя папка с index.ts
  pages/        - страницы, в pages/messenger/blocks блоки, нужные только чату
  controllers/  - контроллеры
  store/        - Store и connect
  services/     - валидация, сбор данных форм, тексты ошибок, подготовка данных
  models/       - типы данных API
  utils/        - queryStringify и isEqual
  routes.ts     - адреса страниц и экземпляр роутера
  main.ts       - точка входа: маршруты, проверка доступа, запуск
ui/             - картинки с макетами
```

Иконки и аватар подключены как Handlebars-партиалы. Имя иконки берётся из файла: `icon-send.hbs` в шаблоне вызывается как `{{> IconSend}}`.
